title: Quick start
description: Create a key, list your Organizations and read their timers over HTTP.
---

This guide runs from your terminal or a server. For code that runs inside
Margonem, use the [game client API](/docs/game-client) instead.

<Steps>
<Step>

### Create an API key

Open [API Keys](/keys) in the environment you want to use and sign in with
Discord. Create a key with at least one Organization and **Read only**
permissions.

The secret is shown only once. Store it as `LOOTLOG_API_KEY` in your server's
environment or secret store.

</Step>
<Step>

### List your Organizations

Send the key in the `X-Api-Key` header. This guide uses development; use
`https://api.lootlog.pl` with a production key.

<Tabs items={["curl", "TypeScript", "Python"]}>
<Tab value="curl">

```bash
export LOOTLOG_API_URL=https://dev-api.lootlog.pl

curl --fail-with-body "$LOOTLOG_API_URL/users/@me/guilds" \
  -H "X-Api-Key: $LOOTLOG_API_KEY"
```

</Tab>
<Tab value="TypeScript">

```ts
const response = await fetch("https://dev-api.lootlog.pl/users/@me/guilds", {
  headers: { "X-Api-Key": process.env.LOOTLOG_API_KEY! },
});

if (!response.ok) throw new Error(`Lootlog returned ${response.status}`);

const organizations = await response.json();
console.log(organizations);
```

</Tab>
<Tab value="Python">

```python
import os
import requests

response = requests.get(
    "https://dev-api.lootlog.pl/users/@me/guilds",
    headers={"X-Api-Key": os.environ["LOOTLOG_API_KEY"]},
    timeout=10,
)
response.raise_for_status()
print(response.json())
```

</Tab>
</Tabs>

The response lists the Organizations the key can reach:

```json
[
  {
    "id": "123456789012345678",
    "name": "My Organization",
    "icon": null,
    "vanityUrl": null,
    "ownerId": "234567890123456789",
    "publicStatsCardEnabled": false,
    "hasLootlogAccess": true,
    "isAccessDataStale": false
  }
]
```

`id` is the Organization's `guildId`. `hasLootlogAccess` tells whether you can
read its Lootlog data right now.

</Step>
<Step>

### Read the Organization's timers

Pass that `guildId` and a world to list the respawn timers of your
Organization:

<Tabs items={["curl", "TypeScript", "Python"]}>
<Tab value="curl">

```bash
GUILD_ID=123456789012345678 # the id from the previous response

curl --fail-with-body -G "$LOOTLOG_API_URL/guilds/$GUILD_ID/timers" \
  -d world=fobos \
  -H "X-Api-Key: $LOOTLOG_API_KEY"
```

</Tab>
<Tab value="TypeScript">

```ts
const organization = organizations.find((item) => item.hasLootlogAccess);
if (!organization) throw new Error("The key cannot read any Organization");

const guildId = organization.id;
const url = new URL(`https://dev-api.lootlog.pl/guilds/${guildId}/timers`);
url.searchParams.set("world", "fobos");

const timersResponse = await fetch(url, {
  headers: { "X-Api-Key": process.env.LOOTLOG_API_KEY! },
});
const timers = await timersResponse.json();
```

</Tab>
<Tab value="Python">

```python
organization = next(
    (item for item in response.json() if item["hasLootlogAccess"]), None
)
if organization is None:
    raise RuntimeError("The key cannot read any Organization")

guild_id = organization["id"]

response = requests.get(
    f"https://dev-api.lootlog.pl/guilds/{guild_id}/timers",
    params={"world": "fobos"},
    headers={"X-Api-Key": os.environ["LOOTLOG_API_KEY"]},
    timeout=10,
)
timers = response.json()
```

</Tab>
</Tabs>

Each timer has its NPC and the window in which it respawns, between
`minSpawnTime` and `maxSpawnTime`.

</Step>
</Steps>

## If the request fails

| Status | Check                                                                    |
| ------ | ------------------------------------------------------------------------ |
| `401`  | The key and the URL belong to the same environment, and the key is valid |
| `403`  | The key includes this Organization and you can read its timers           |
| `404`  | The `guildId` is right and the Organization is visible to you            |
| `429`  | Wait for `Retry-After` seconds before you send another request           |

[Errors, pages and limits](/docs/errors) explains every status and the error
body.

## Explore the API reference

The [API Reference](/reference) lists every operation of the four services with
its parameters and response schema. Paste your key into the `X-Api-Key` field
to send requests from the page. The portal does not store the key, and requests
go straight to the selected environment.

Use `GET /openapi/main.json` (and `activity.json`, `battlelog.json`,
`search.json`) on this portal to download the OpenAPI documents for your own
tools.
