Lootlog connects a Margonem game client, a web app and Discord. Players record
timers, loot, kills and battles as they play, and their group shares them in
one place. As a developer you read and react to the same data: a Discord bot
that posts respawns, a dashboard of your clan's loot, or an add-on that shows
timers inside the game.

## Concepts

**Organization.** The group your data belongs to. Each Organization is anchored
to one Discord server and usually represents one faction, which can include
several Margonem clans and players without a clan. Players see an Organization
as a _Lootlog_. API paths and fields call its Discord server a `guild`, so
`guildId` is the Organization's Discord server ID.

**User and Member.** A User is a person with a Lootlog account, signed in with
Discord. A Member is a User whose Discord membership places them in an
Organization. Discord roles decide what a Member can read and change.

**Player and world.** A Player is a Margonem character. Timers, loot and kills
belong to one world, such as `fobos`, so most lists take a `world` filter.

**Access follows the user.** An API key acts as the User who created it. It
reaches only the Organizations selected for the key, and inside them only what
that User can access in Lootlog right now. See
[keys and permissions](/docs/keys).

## Services

Lootlog is split into five HTTP services. One API key works for all of them.

| Service   | Base URL                       | What it serves                                         |
| --------- | ------------------------------ | ------------------------------------------------------ |
| Main API  | `https://api.lootlog.pl`       | Organizations, Members, timers, loot, kills and events |
| Activity  | `https://activity.lootlog.pl`  | The activity log, Member activity and your online time |
| Battlelog | `https://battlelog.lootlog.pl` | Recorded battles and their analytics                   |
| Catalog   | `https://catalog.lootlog.pl`   | Margonem items and NPCs, and the item and NPC catalog  |
| Search    | `https://search.lootlog.pl`    | Player search by name                                  |

Changes are also delivered over WebSocket by the
[realtime gateway](/docs/realtime), so you do not need to poll.

## Environments

Every service also runs in development. Keys are separate per environment:
create one in the development portal to test, and another in production for
real data.

| Environment | Developer portal                   | Main API                     |
| ----------- | ---------------------------------- | ---------------------------- |
| Development | `https://dev-developer.lootlog.pl` | `https://dev-api.lootlog.pl` |
| Production  | `https://developer.lootlog.pl`     | `https://api.lootlog.pl`     |

Other development hosts add the same `dev-` prefix, for example
`https://dev-search.lootlog.pl`.
