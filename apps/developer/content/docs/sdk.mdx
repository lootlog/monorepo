`@lootlog/sdk` is generated from the same OpenAPI documents as the
[API Reference](/reference), so every operation, parameter and response is
typed. It has no React dependency and runs on a server, for example in Node.js
or Bun.

## Configure

Call `configureLootlogApi` once with your key and environment. It returns a
cleanup function that removes the configuration.

```ts
import { configureLootlogApi } from "@lootlog/sdk";

const apiKey = process.env.LOOTLOG_API_KEY;
if (!apiKey) throw new Error("Missing LOOTLOG_API_KEY");

const cleanup = configureLootlogApi({ apiKey, environment: "development" });
```

Omit `environment` for production. Pass `fetch` to use your own HTTP client, or
`baseUrls` to point a service at another host.

## Read data

Each service has its own entry point: `@lootlog/sdk/main`,
`@lootlog/sdk/activity`, `@lootlog/sdk/battlelog` and `@lootlog/sdk/search`.
Function names follow the operation IDs in the reference.

```ts
import {
  timersControllerGetTimers,
  usersControllerGetCurrentUserGuilds,
} from "@lootlog/sdk/main";

const [organization] = await usersControllerGetCurrentUserGuilds();

const timers = await timersControllerGetTimers(
  { guildId: organization.id },
  { world: "fobos" },
);

for (const timer of timers)
  console.log(timer.npc.name, timer.minSpawnTime, timer.maxSpawnTime);
```

Pass `{ signal }` as the last argument to cancel a read with an
`AbortController`.

## Read every page

Lists return `{ items, nextCursor }`. Pass the cursor back with the same
filters until it is `null`:

```ts
import { lootsControllerFetchLootsByGuildId } from "@lootlog/sdk/main";

let cursor: string | undefined;

do {
  const page = await lootsControllerFetchLootsByGuildId(
    { guildId: organization.id },
    { world: "fobos", limit: 100, cursor },
  );

  for (const loot of page.items) console.log(loot);
  cursor = page.nextCursor ?? undefined;
} while (cursor);
```

## Handle errors

A failed request throws an `Error` with the response `status` and the parsed
[error body](/docs/errors#error-body) in `data`:

```ts
try {
  await timersControllerGetTimers({ guildId }, { world: "fobos" });
} catch (error) {
  const status = (error as { status?: number }).status;
  const body = (error as { data?: { code?: string } }).data;

  if (status === 403) console.warn("The key cannot read these timers");
  else if (body?.code === "RATE_LIMITED") console.warn("Slow down");
  else throw error;
}
```

The SDK never retries a write on its own. See
[errors, pages and limits](/docs/errors) for when a retry is safe.

## Realtime

`@lootlog/sdk/realtime` provides `RealtimeClient`. Give it a server-side
`webSocketFactory` that adds the `X-Api-Key` header, and the gateway of your
environment. Never put the key in the URL. The
[realtime guide](/docs/realtime#bun-example) has a complete Bun example.

## Userscripts

A userscript does not need the SDK. It calls `window.lootlogGameClientApi`
directly; the optional `@lootlog/game-client-api` package adds editor types.
See the [game client API](/docs/game-client).
